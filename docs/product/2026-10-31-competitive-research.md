# 招投标同类产品调研与 BidCopilot 升级建议

- 日期：2026-10-31
- 范围：国内商机/标讯平台、国内标书与 AI 投标工具、国际 RFP / bid 管理软件
- 方法：优先官网定价页与产品页；二手测评、软文与厂商宣称单独标注，不作为定价或能力事实
- 证据分级：`官网` = 官方页面直接确认；`二手` = 第三方测评/媒体，未核实；`厂商宣称` = 无第三方审计的效果数字
- 价格口径：均为调研日公开页面所示，币种与计费单位按原文；"询价"表示官网未公开价格

## 0. 定位更正（2026-10-31 收尾，优先于本文其余部分）

本文档早期把目标客群写成“**招标代理/代理机构**”，这是**错误定位**，已作废。更正如下：

**产品只面向企业投标部门（单一投标主体）。不面向招标代理机构。**

理由：招标代理是受招标人委托、**主持招标程序**的一方，必须保持中立。若一个机构既主持某项目招标、
又替该项目的投标人写投标文件，即构成利益冲突与串通投标风险。因此“代写投标文件的工具”在业务上
不可能卖给招标代理。本文 §3.2 里“标书啦/标书客 人工代写”一类才是同类业务，但它们的客户是
**投标企业**，不是招标代理。

由此产生的直接后果（已落地的代码变更）：

| 原表述 | 更正后 |
|---|---|
| 目标客群优先“代理机构” | 目标客群是**企业投标部门**；标书代写公司可作为渠道，但产品主体仍是单一投标方 |
| “多客户工作台”（P0-1） | **能力已整体下线**：`clients`/`client_members` 表与 6 张表的 `client_id` 列、`client_limit` 均已通过迁移 `0068_retire_client_scope` 删除 |
| “按客户分摊成本”（P0-2） | 分摊能力删除；AI 计量保留**按项目**维度（`ai_usage_ledger` 仍记 project 维度篇数/字数） |
| “代理白标交付”（P0-5） | 白标诉求作废。导出品牌改为**投标企业自身名称**（`Company.name`），无企业时回退 `BidCopilot`；不做弱化工具品牌 |
| “招标文件体检”并入主线（P1-6） | 该能力面向**采购人/招标代理**（检查招标文件是否违规），与本产品主线不同源，故**不占主菜单**，保留为独立工具页 `/file-check` |
| 跨投标人雷同自查（P1-7） | 定位为**投标人交标前合规终检**，已并入「投标项目 → 响应与自查」阶段，不再独立成菜单 |

菜单结构同步收敛（详见 §8.2）：一级菜单由 8+7 项降到 7+4 项，账号设置移入左下角头像区。

## 1. 结论摘要

1. **国内商机平台已是红海，且数据同源。** 官方平台免费发布，商业平台（剑鱼、千里马、采招网、导航网）卖的是聚合、提前量、联系人、历史中标与导出。年费从 C 端 199–3,880 元到 B 端 4,800–60,000 元，普遍电销 + 纸质合同成交。BidCopilot 不应正面做数据平台，KeepRisk 继续作为数据供给，产品价值放在“拿到商机之后的工作”。
2. **AI 编标工具进入价格战，但只解决“写”。** 从 9.9 元/份（钛投标，二手）、49.9 元/20 万字（易标，官网）到 199 元/月（快标书，官网渠道）与 5,800–29,800 元/年（智标，二手），同质化严重；普遍“AI 出初稿 + 人工复核”，且明确不承担废标责任。
3. **平台系厂商的壁垒是交易平台直连。** 新点、广联达把清标、计价、CA 签章、加密与上传嵌进电子招投标流程，按项目/加密锁收费。BidCopilot 的非目标（自动投标/CA 签章）恰好是这条壁垒，短期不应硬碰，改做“导出 + 交标就绪 + 回执人工确认”。
4. **国际 RFP 软件按席位 + 平台费 + 实施费收费，价格普遍不公开。** DeepRFP 公开 $89–149/用户/月（官网），Tendium Light €125/月、其余询价（官网），Loopio 三档询价且 Foundations 最少 10 席（官网）。Responsive 二手估算约 $299/用户/月 + 平台费、年均约 $13,955（二手）。
5. **代理机构是结构性空位。** 国内产品要么卖标讯、要么卖写标书、要么卖交易系统；“多客户 + 多项目 + 权限隔离 + 白标交付 + 按项目核算”的代理机构工作台很少（招采星提到“代理机构项目管理系统”，钛投标宣称适配代理，均未验证深度）。这与 BidCopilot 现有能力（多租户、RBAC、项目工作区、成本台账）距离最近。
6. **政策给了明确的需求侧理由。** 发改法规〔2026〕195 号列出 20 个场景，其中第 4 条“投标策划”、第 5 条“投标合规自查”（技术方案与报价区间、逐条响应比对、缺漏/违规提示、低于成本价预警）与本系统主线高度重合；第 8 条“智能辅助评标”、第 11 条“中标合同签订”是邻接场景。
7. **收费模式的机会是“透明 + 按项目/按篇 + 私有化溢价”。** 竞品普遍价格不透明、退款纠纷多（千里马投诉样本）、隐藏实施费（Responsive 二手）；BidCopilot 可用“公开价目 + 按篇 credits + 私有化年费”建立信任差异。
8. **不建议做能力清单军备竞赛。** 更优路径是把“证据链 + 确定性合规 + 私有化 + 代理多客户”做成窄而深的差异化，而不是追“10 分钟出稿”“准确率 99%”这类厂商口径。
9. **股权穿透/工商数据源已具备，判断更新。** 原本“缺数据源、搁置”的关联关系能力可产品化为“关联关系核验/尽调辅助”（见 6.7），但只做风险提示与依据链，不做串标定性、不做规避检测。

## 2. 市场与政策底座

### 2.1 政策：AI 进入招投标的 20 个场景

发改法规〔2026〕195 号（2026-02-06，国家发改委等 8 部门）明确：2026 年底招标文件检测、智能辅助评标、围串标识别等重点场景在部分省市全覆盖；2027 年底更多场景全国推广。文件同时规定：**模型结论不替代投标人、招标代理机构、评标专家等的自主判断，不改变使用主体的法定责任**；要求防范模型黑箱与幻觉。

与本系统相关度：

| 政策场景 | 与本系统关系 | 现状 |
|---|---|---|
| 4. 投标策划 | 商机同步、匹配、Bid-No-Bid、报价策略 | 已覆盖大半 |
| 5. 投标合规自查 | 逐条响应、29 条确定性规则、缺漏/违规提示、低于成本价预警 | 核心强项，需补“交标终检” |
| 8. 智能辅助评标 | AI 评标模拟（投标侧预演） | 已有，但非官方评标 |
| 11. 中标合同签订 | 合同审查、承诺对照、履约台账 | 已有，可加强“中标→合同”衔接 |
| 1–3 招标侧 | 招标文件编制/检测 | 未做；对代理机构是增量机会 |
| 16–20 监管侧 | 围串标识别、关联关系核验等 | 不做监管产品；依托自有工商/股权数据做**采购人与投标人侧的关联关系核验**，只输出风险提示与依据，不做串标定性、不做规避检测 |

### 2.2 市场数字不采信

二手文章对“招投标市场规模”给出 4.2 万亿、38.7 万亿、48.6 万亿等互相矛盾的数字，且多为报告销售页或 SEO 软文；本报告不使用这些数字做判断。可确认的只有结构性事实：官方平台免费、商业平台做聚合、电子化率高、AI 场景被政策明确推动。

## 4. 收费模式拆解

| 模式 | 代表 | 价格锚点 | 适合谁 | 风险 |
|---|---|---|---|---|
| 数据订阅年费 | 千里马/采招网/剑鱼 | 7,999–21,999 元/年；企业 5 万/年含 10 席 | 销售驱动、需要联系人 | 数据同源、退款纠纷、价格不透明 |
| 按字数/按篇 | 易标/文兜/钛投标 | 49.9 元/20 万字；6 元/万字；9.9 元/份（二手） | 低频、预算敏感 | 价格战、无交付责任 |
| 月卡/年费 SaaS | 快标书/智标 | 199 元/月；5,800–29,800 元/年 | 高频编标团队 | 同质化、知识库冷启动 |
| 平台/项目制 | 新点/广联达 | 询价、加密锁、项目制 | 政府/央企/工程 | 直连壁垒、实施重 |
| 人工代写 | 标书啦/采招网 | 800–3,000 元/份起 | 一次性交付 | 不可规模化、质量依赖写手 |
| 国际席位制 | DeepRFP/Tendium/Loopio | $89–149/用户/月；€125/月起；企业 2.5–14.2 万美元/年（二手） | 专业 bid 团队 | 实施费、最低席位 |
| 签署按份 | e签宝/法大大 | 650 元/100 份起 | 签署环节 | 与编标不直接竞争 |

**结论**：国内客户已被“年费 1–2 万”教育过，也对“按篇几十到几百”有感知；BidCopilot 若只卖“又一个 AI 写标书”，会被拖进 49.9 元/20 万字的价格战。应把计费锚定在“项目交付 + 合规风险 + 多客户协同”，而不是字数。

## 6. 对本系统的启示

### 6.1 定位：不做数据平台，做“投标交付工作台 + 合规证据链”

- 商机数据继续经 KeepRisk，不自建全国标讯采集；否则会陷入数据同源与电销成本。
- 与 AI 编标工具的区别：BidCopilot 的护城河是**证据溯源、确定性合规、私有化、多租户/审计**，不是“生成更快”。
- 与平台系厂商的区别：不碰 CA/签章/加密上传，做**导出 + 交标就绪清单 + 回执人工确认**，与交易平台服务商合作而非对抗。
- 目标客群是**企业投标部门**（单一投标主体）；标书代写/投标咨询公司可作为渠道伙伴，但不构成“多客户”产品能力（见 §0 定位更正）。

### 6.2 功能升级路线（按“谁付钱、解决什么”排序）

**P0（0–3 个月，决定能否卖给企业投标部门）**

2. **按项目/按篇计量与套餐**：在现有 `cost_ledger`/`paid_call_quotas` 之上增加项目计量与套餐权益（项目数、席位数、AI 篇数/字数），支持“按项目结算 + 超额用量”。**2026-10-31 已实现额度与 AI 产出侧计量（`ai_usage_ledger` 按项目记篇数与字数、套餐 `ai_piece_limit`/`ai_word_limit` 超限 429、`GET /projects/{id}/ai-usage`）；按客户分摊与 `/clients/{id}/ai-usage`、`/costs/ai-usage/by-client` 已随多客户能力一并删除；支付/发票仍未做。**

5. ~~**代理白标交付**~~ → **改为「以投标企业自身名义交付」**（2026-10-31 收尾）：企业以自己的名义投标，不需要“弱化工具品牌”的白标诉求。导出品牌取 `project.company_id` 对应企业的名称（`Company.name`），无关联企业时回退 `BidCopilot`；docx/xlsx/PDF 均内嵌该品牌名，暗标导出自动剔除品牌；审计记录交付品牌，Logo 缺失不导致导出失败。`clients.brand_name`/`brand_logo_url` 随客户能力一并删除。

## 7. 风险与反例

1. **数据版权与平台条款**：商机数据经 KeepRisk 合约使用；不自建爬虫，避免 195 号与平台条款风险。
2. **AI 幻觉与责任**：坚持“模型结论不替代人工判断”，所有事实核查留痕；对外不承诺中标/零废标。
3. **代理多客户隔离**：这是 P0 的架构改动，若只做 UI 不做数据隔离，会重演“项目级 ACL 缺失”的问题。
4. **价格战**：按字数计价会被 49.9 元/20 万字拖死；必须把价值锚定在项目交付与合规。
5. **平台系直连壁垒**：短期不碰 CA/上传，长期通过合作或标准导出适配切入。
6. **国际化的合规成本**：GDPR/数据驻留/安全认证（SOC 2）投入大，非当前优先级。
7. **工商/股权数据合规**：需确认数据授权范围、可转售条款、个人信息最小化与用途声明；产品输出必须限定为“风险提示+依据”，不做串标定性；查询与导出全量留痕。

## 8. 证据缺口

- 智标、文兜、筑龙、钛投标价格为二手，官网价格页 403 或仅活动页；未核实。

#### 走查中发现并修复的真实缺陷：纯大纲式文档丢失全部章节

`knowledge/template_autogen.py::_segment_chunk` 只在「缓冲区非空」时产出片段，因此
**标题后紧跟标题（无正文）**时，前一个标题被整体丢弃。一份只写章节标题的历史标书
（纯目录结构）会因此丢掉所有章节，并被报成「请确认文档带标题层级」——与事实相反。

修复（`_segment_chunk`）：标题无正文时补一个空正文片段以保住章节骨架；空正文**不得**伪造
`required_materials`（材料线索仍只来自真实证据）。同时把报错信息区分为两种成因：

- 完全没识别到标题 → 「文档中未识别到任何章节标题，请确认使用『第一章 / 1.2 技术方案』这类带编号的标题行」
- 识别到标题但种类不够 → 「已识别到标题但不同章节过少（N 个：…），请补充章节层级更完整的案例文档」

新增 2 条回归用例（`tests/unit/test_template_autogen.py`）：
`test_build_sections_keeps_sections_when_titles_have_no_body`、
`test_build_sections_error_distinguishes_missing_headings_from_few_sections`。
后端全量由 776 → **778 passed, 2 skipped**。

#### 审计链完整性：线上演示库为 False，但**不是代码缺陷**

`GET /api/v1/audit/verify` 在演示租户返回 `valid=false`。逐条复算定位（只读，不改数据）：

```
事件数=3887  seq 范围=1..4072  缺口段数=15
断裂归因：seq 缺口（事件被删除）=8   代码级完整性失败=0
```

即：8 处断裂**全部**落在 seq 缺口之后（`prev_hash` 指向已被删除的事件），
用实际前一条存续事件重算 hash 时**没有一处失败** → 链算法正确，是历史数据被删。

根因：**生产代码没有任何删除 `audit_events` 的路径**（全仓 grep 为空，append-only 未被破坏）；
删除来自测试清理（`tests/**` 里多处 `delete(AuditEvent).where(tenant_id=...)`）在某个时点
直接跑到了演示库上。断点发生在 2026-10-29，早于本轮工作。

算法本身双向验证（`tests/integration/test_audit_api.py`）：
干净链 4 条 → `{"valid": true, "events": 4}`；篡改任一事件后 → `valid: false`。

**未修数据**：审计记录属不可逆持久态，删除或重写均违反「审计只追加」，
需由数据属主决定是否接受（可选项：保留现状并说明、或换用全新租户做演示）。

### 8.2 菜单结构按业务定位收敛（2026-10-31 收尾）

原则：**菜单是业务定位的投影，不是功能清单**。按“企业投标部门做一件事的真实顺序”排，不为加功能而加菜单。

收敛前（一级菜单 8 + 7 + 1 + 1 = 17 项）：

- 投标工作流 8 项：指挥台 / 机会中心 / 投标项目 / 合同台账 / 企业资产 / **文件体检** / 企业知识库 / 模板与技能
- 运营与治理 7 项：数据运营 / 审计日志 / 合规策略 / **用户管理** / **权限治理** / **客户管理** / **账号设置**

收敛后（一级菜单 7 + 4 + 1 + 1 = 13 项）：

| 分组 | 菜单 | 变更理由 |
|---|---|---|
| 投标工作流 | 指挥台 / 机会中心 / 投标项目 / 合同台账 / 企业资产 / 企业知识库 / 模板与技能 | 按投标动线：找机会 → 做标 → 交标 → 中标履约；资产/知识库/模板是“弹药库” |
| 运营与治理 | 数据运营 / 审计日志 / 合规策略 / **成员与权限** | 见下 |
| 平台 | 平台租户（现为企业版闭源能力） | 2026-11 起多租户运营划入商业授权 |
| 帮助 | 使用帮助 | 不变 |

具体删除与合并：

1. **删「客户管理」**：企业投标部门是单一主体，多客户能力已整体下线（迁移 `0068_retire_client_scope`），菜单自然消失。
2. **删「账号设置」一级项**：它是**个人**设置，不是租户治理。改为进入左下角用户卡片——收起态头像、展开态头像 / 用户名 / 齿轮图标，共 **4 个入口**都指向 `/settings`。
3. **「用户管理」+「权限治理」合并为「成员与权限」**：两者都是 `user:manage` 权限、服务同一批人——一个管“谁在租户里”，一个管“谁能看什么”，是两个菜单一个权限。菜单只保留一个入口指向 `/users`；`/users` 与 `/access` 两页顶部各加一组互相切换的分区标签（「成员与角色」/「部门与权限策略」），帮助文档的节名同步为「成员与权限 · 成员与角色」「成员与权限 · 部门与权限策略」，避免用户按帮助里的名字找不到入口。
4. **「文件体检」移出一级菜单**：
   - 其「跨投标人雷同自查」是**投标人交标前合规终检**，与就绪清单、自查清单回答同一个问题，已并入「投标项目 → 响应与自查」阶段（组件 `BidderSimilarityPanel`）。
   - 其「招标文件体检」是**买方侧工具**（检查招标文件是否指定品牌/限制地域），与产品主线不同源，保留为独立工具页 `/file-check`；入口放在「投标项目 → 解析与决策」区右上（决策阶段判断招标文件是否值得投），不占主线菜单。
5. **「合规策略」可见权限修正**：原为 `project:read`，导致标书工程师（有 `project:read`、无 `project:approve`）也能看到自己改不了的配置页；改为 `project:approve`，与后端 `PATCH /policies/{id}` 的实际写权限对齐——只有真正能改规则的人（合规/法务、企业管理员）看到入口。

**可达性自检（本轮实测）**：21 个路由页面逐个核对，除 `/`（入口）与 `/login`（公开）外，**无不可达页面**——菜单 13 项 + 页面内链接覆盖其余路由。

保留但已知局限：`/readyz` 未经 nginx 反代（见上节缺口清单）。

### 8.3 交互反馈一致性（2026-10-31 第三轮）

起因：用户反馈「点完不知道下一步在哪」。排查后确认这不是单点问题，而是**三类系统性问题**，逐一收口。

#### 一、阻断提示只说状态、不说动作

「解析与决策仍有阻断：尚未解析招标文件」——说了有问题，没说该点哪。

修复：把后端阻断文案映射为「动作 + 目标阶段 + 目标锚点」：

| 后端阻断文案 | 界面动作 | 点击后落到 |
|---|---|---|
| 尚未解析招标文件 | 上传招标文件 | 解析与决策 → 招标文件卡片 |
| 尚未生成大纲 | 去选模板生成大纲 | 标书生产 → 模板与大纲 |
| 尚未生成章节 / 尚无审批通过的章节 | 去生成/审批章节 | 标书生产 → 章节面板 |
| 导出前需审批章节 | 去生成/审批章节 | **跳到标书生产**（不在合规页） |
| 尚未运行合规预检 | 去跑合规预检 | 合规与交付 → 合规面板 |

主按钮同步改为 `下一步：<动作>`；点击后滚动到目标卡片并播放 2.1s 描边脉冲（`outline` 实现，不占布局，尊重 `prefers-reduced-motion`）。

#### 二、危险操作没有二次确认

审计全部 156 个按钮：**9 处删除类操作无确认**（仅 1 处有）。新增 Promise 式统一确认框 `components/confirm-dialog.tsx`，接入全部 9 处，且每处写明**具体后果**而非泛泛的「确定删除吗」：

- 删除交标回执附件 → 「这是交标回执的合规留痕，删除后附件与对象存储内容同时清除且无法恢复」
- 吊销 API 令牌 → 「集成方会开始收到 401，需重新签发并替换配置，不可撤销」
- 删除 Webhook → 「接收方不再收到事件推送，已投递记录一并不可查」
- 其余（撤销个人 Key / 删除通知渠道 / 撤销知识库授权 / 停止监控 / 删除订阅）同样写清影响范围与「什么不受影响」

不用 `window.confirm` 的理由：写不下后果、阻塞主线程、内嵌浏览器可能禁用、jsdom 无法测试。

#### 三、空状态与失败态不给下一步

审计 33 处 `EmptyState`：**17 处只写「暂无 X」**；另有 7 个含 `useQuery` 的文件**完全没有失败分支**——请求失败时界面停在「加载中…」或误显示「尚未生成」，让用户误判为「没数据」。

修复：
- `EmptyState` 扩展为 `text`（为什么空）+ `hint`（下一步做什么）+ `action`（可直接点的入口）；17 处全部补齐，首页与模板页加了真实跳转按钮。
- 新增 `ErrorState`（显示后端 message + 重试），接入 dashboard / templates / compliance-panel / commitments-panel / workspace-stages。
- `workspace-stages` 此前查询失败会永远显示「加载阶段…」，现改为明确报错 + 重试。

#### 四、重复提交

`Button` 增加自动防重复：`onClick` 返回 Promise 时在结束前禁用自身并置 `aria-busy`。
注意边界：`() => mutation.mutate()` 这类同步写法拿不到 Promise，仍需调用方传 `disabled={mutation.isPending}`（已在代码注释中写明，未夸大）。
